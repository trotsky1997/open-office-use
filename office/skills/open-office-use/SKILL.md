# Open Office Use

Read the office/README.md for installation, commands, MCP tools, spec formats and limitations. For multi-step work, use a session directory and pass the latest revision as the base for each edit. The viewer can preview earlier revisions before `session_restore` or its restore control copies a prior revision into a new revision when requested. When a user wants to watch progress, run `office-use watch` for the session and share its local URL. The viewer can search a saved selection for candidate paths; the user can choose a candidate to load. The viewer and MCP can load and edit supported elements by explicit path; verify the element and version first. If the user selects an area, read `session_selection`, `session_selection_image` and, when useful, `session_selection_text` and `session_selection_candidates`; check its revision and stale flag, then verify candidate elements with structured reads and visual context. Repeated or missing text can produce ambiguous results. Selected PDF text may omit image or partially selected text. Inspect source files before editing. Write to a new output path. For structured operations use OfficeCLI through `office-use structured` and `office-use batch` when installed. Save and close the source first. Run `audit` or `audit_file` and inspect validation and issues before delivery. Use `compare` or `compare_files` to review text and package changes in saved files; inspect the actual content and rendered pages for details. Use `office-use preview` to render page PNGs and inspect them visually before delivery. Use `cells` or `read_cells` to inspect formulas and cached values. Cache freshness is unknown. When appropriate, use `recalculate` or `recalculate_workbook` to make a LibreOffice-calculated copy, check errors, and review conversion fidelity. Inform the user about any fidelity or feature limitations relevant to their file.
