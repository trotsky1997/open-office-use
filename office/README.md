# Open Office Use — early local harness

A first office-file workbench in the [iFurySt/open-browser-use](https://github.com/iFurySt/open-browser-use) fork. It offers a JSON CLI for local DOCX, XLSX and PPTX inspection, creation, limited edits, and PDF rendering. It does not require Chrome. The inherited browser tooling remains available under its original name.

## Install

Python 3.10+. PDF rendering requires LibreOffice on PATH; page PNG previews additionally require Poppler `pdftoppm`, and selected text extraction requires `pdftotext`. The structured operations below require OfficeCLI on PATH (tested with 1.0.147):

```sh
python3 -m pip install ./office
```

The Codex skill is discoverable from the repository root and can be installed separately:

```sh
npx skills add trotsky1997/open-office-use -g -a codex --skill open-office-use -y
```

The skill supplies agent guidance and links format-specific Word, PowerPoint and spreadsheet references; install the CLI and, for MCP, the optional dependency as described below. OfficeCLI, LibreOffice and Poppler are separate system tools.

Run `office-use doctor` to probe the available executables, versions and optional MCP import. MCP clients can call `office_doctor` for the same report. Capability flags summarize the dependencies used by structured authoring, PDF rendering, page images and selected-text extraction. A successful version probe confirms startup only; it does not validate a document or guarantee rendering fidelity. The command returns a report even when dependencies are missing.

## Use

```sh
office-use inspect report.docx
# Create a document from a JSON specification
office-use author --spec doc.json --out report.docx
# Edit a copy of an existing file
office-use author --source input.xlsx --spec edits.json --out output.xlsx
office-use render output.xlsx --out-dir pdfs
office-use preview output.xlsx --out-dir page-images
```

MCP `author_file` accepts the same JSON object as `spec`, an `output` path, and optional `source`; it returns the new output path. This basic authoring path does not require OfficeCLI. The command writes one JSON result to stdout, reports failures to stderr and returns a nonzero status. Output files must not already exist. Inspect returns zero-based paragraph and slide indices; PPTX inspection includes each text shape’s index in the underlying shape collection.

`author` and `render` prepare each output in a temporary directory on the destination filesystem, then publish it with an exclusive hard link. Failure before publication leaves no output from that attempt; a competing writer's output is preserved. Filesystems without hard-link support return an error. A forcibly interrupted process may leave its temporary directory behind. When editing an XLSX copy, `author` rejects workbooks with unverified shared strings; supported targeted session edits remain available.

Use `office-use search-word report.docx --query 'Revenue'`, `office-use session search-word ./draft --revision 0 --query 'Revenue'`, or MCP `search_word_body` / `session_search_word_body` to locate case-sensitive literal text in body and nested table paragraphs. Results provide candidate paths for `session_replace_text`, bounded excerpts and overlapping occurrence counts. Each page scans up to 10,000 paragraphs and returns at most 100 matches; when `next_offset` is present, continue with the same query, the returned offset and `snapshot_sha256` (`--offset` and `--snapshot-sha256` in the CLI). A changed snapshot is rejected. `scan_complete`, `complete`, `unverified_paragraphs` and `unsupported_structure` describe coverage for the scanned page. Headers, footers, notes, text boxes and unsupported wrappers are outside this search; use `stories` for supported headers and footers. Complex paragraph content may be omitted or joined differently from the rendered view. Inspect the target, require an unambiguous match and let targeted edit validation check the paragraph before modifying it. Search copies the saved DOCX and enforces the 5,000-part and 128 MiB package limits.

For Word footnotes and endnotes, use `office-use search-word report.docx --scope notes --query 'Revenue'`, the corresponding session command, or MCP `search_word_notes` / `session_search_word_notes`. Results include note identifiers, paragraph paths, excerpts and coverage information; pagination uses the same query and snapshot hash. The viewer offers a Footnotes and endnotes scope and opens matching paragraphs in the targeted replacement editor. Ordinary note paragraphs and supported tables are covered; separator notes and unsupported structures are excluded or flagged. Replacement preserves supported run formatting and the note marker; references to the same note ID share its text. Inspect the saved document and review unsupported fields or tracked changes separately.

For related Word headers and footers, use `office-use search-word report.docx --scope stories --query 'Revenue'`, the corresponding session command, or MCP `search_word_stories` / `session_search_word_stories`. The viewer's search scope selector offers the same operation. Results contain relationship-based paragraph paths and package parts, including supported tables. The same paragraph and result limits, snapshot-bound pagination, uncertainty and structure coverage fields apply. Up to 200 header/footer relationships are searched; other document stories are outside this scope. A part shared by multiple relationship IDs appears for each ID. Load a result to inspect linked sections before editing; display of first/even variants depends on page settings and pagination. Viewer targets over 4,000 characters remain unavailable.

Inspect saved PowerPoint chart caches with `office-use inspect-slide-charts deck.pptx`, `office-use session inspect-slide-charts ./draft --revision 0`, or MCP `inspect_slide_charts` / `session_inspect_slide_charts`. Results identify charts, slide and shape IDs, cached series values, category labels, source formulas, and embedded-workbook part hashes. Category labels are returned as strings. Reconciliation compares chart caches with saved values in embedded workbooks and reports match, mismatch, incomplete or unavailable per chart. A mismatch can coexist with unverified source points; check both `status` and `complete`. Formula result freshness remains unknown. Reconciliation covers at most 20 charts, 16 MiB per embedded workbook and 64 MiB across workbooks, with at most 30 returned references and three mismatch examples per reference; per-chart completeness is independent of inventory completeness. External workbook relationships are reported without fetching the target. The inventory scans at most 200 slides, 10,000 shapes, 100 charts, 30 series per chart and 5,000 cached points; a series or category list over 200 values is marked incomplete. `complete`, `issues`, `issue_count` and `issues_truncated` report coverage. Complex chart structures and missing or malformed caches may be incomplete. Review the embedded workbook and rendered slides before relying on the data. PPTX review bundles include this inventory and flag mismatches, incomplete reconciliation and external workbook inspection.

For presentations, `office-use search-slides deck.pptx --query 'Revenue'`, `office-use session search-slides ./draft --revision 0 --query 'Revenue'`, and MCP `search_slide_text` / `session_search_slide_text` search shape and table paragraphs, including supported groups and hidden slides. Supply `--slide` or `slide` for a one-based slide number. Results include candidate paths, hidden-slide status, occurrence counts and bounded excerpts. Each page scans at most 10,000 items (shapes and paragraphs) and returns at most 100 matches; continue with `next_offset` and `snapshot_sha256`, preserving the query and slide. Check coverage fields for unsupported structures or uncertain text. Masters, layouts, notes, charts and SmartArt content are outside the search. Paths and text are candidates for targeted editing; inspect the slide and let edit validation check the target. Search uses a saved snapshot and enforces the same package limits as Word search.

To search speaker notes, add `--scope notes` to either `search-slides` command, or pass `scope: "notes"` to MCP `search_slide_text` or `session_search_slide_text`. The viewer offers a Speaker notes search scope and opens a selected result in the notes editor, filling its paragraph number and a unique matching query. The same snapshot-bound pagination and limits apply; continue with the same scope and slide selection. Results cover notes-body paragraphs, including hidden slides; other notes shapes and masters are excluded. Complex runs can make text incomplete. Review the result before editing; the targeted replacement validates its paragraph and preserves supported run formatting.

Read chart data with `office-use session read-slide-chart-grid ./draft --revision 0 --part /ppt/charts/chart1.xml --sheet Sheet1 --range A1:B3`, or MCP `session_read_slide_chart_grid`. Edit it with `office-use session edit-slide-chart-grid ./draft --base 0 --part /ppt/charts/chart1.xml --sheet Sheet1 --range B2 --changes '[{"cell":"B2","value":"125"}]'`, or MCP `session_edit_slide_chart_grid`. Use the chart part and source sheet from chart inspection. Grid editing supports up to 200 cells with the same protection and formula-range checks as workbook grid editing. It creates a new presentation revision, preserves the original embedded workbook package outside the grid edit, and may reserialize the chart XML. Other charts sharing the workbook can also be affected. Chart caches and formula results may become stale; inspect and synchronize each supported mismatched reference, recalculate if needed, and review the rendered presentation. To update comparable caches in the same revision, add `--sync-caches` or set MCP `sync_caches: true`. This requires a complete inventory and matching caches before editing, fully comparable caches afterward, no reachable uninspected workbook relationships, and at most 30 changed references. All affected inspected charts sharing the workbook are synchronized. Any failure leaves the revision unpublished. Formula-source caches are not opted in, and formula result freshness remains unknown. Data-validation rules are reported but not evaluated. Embedded workbooks are limited to 16 MiB.

To repair a fully comparable mismatched PowerPoint chart reference, use `office-use session sync-slide-chart-cache ./draft --base 0 --part /ppt/charts/chart1.xml --reference 1` or MCP `session_sync_slide_chart_cache`. Select the chart part and reference index from the inspection result. This creates a new revision, updating or adding points for verified values and removing points for verified blank cells; the embedded workbook stays intact. Formula-source caches require explicit `--allow-formula-caches` / `allow_formula_caches: true` after review, and their freshness remains unknown. Unsupported references, unverified source values, external workbooks and chart extensions are rejected.

For XLSX, `inspect` and MCP `inspect_file` return a bounded sparse sample of stored cells. They inspect up to 50 worksheets, scanning up to 10,000 stored cells and returning up to 100 populated cells per sheet, with values clipped to 500 characters. Recognized hidden worksheets are included and chart sheet names are reported separately; unsupported sheet types can be omitted by openpyxl. `sample_complete`, `worksheets_truncated`, `chartsheets_truncated`, `value_truncated` and `text_complete` describe the limits. Declared dimensions can be inaccurate. Numeric and date samples are raw stored values; shared-formula followers can lack formula text. `text_complete: null` indicates missing formula text; unverified shared strings and raw Excel escape sequences are marked incomplete. Use `cells` or `read_cells` for decoded values in a specific range and review formula caches separately. The inspector reads a saved snapshot, rejects packages exceeding 5,000 parts or 128 MiB uncompressed, and loads the shared-string table through openpyxl. `office-use session inspect-workbook ./draft --revision 0` and MCP `session_inspect_workbook` inspect an exact revision. The viewer's “Workbook overview” displays the same sample for its displayed revision.

To locate text outside that sample, use `office-use search-cells book.xlsx --query 'Revenue'`, `office-use session search-cells ./draft --revision 0 --query 'Revenue'`, or MCP `search_cells` / `session_search_cells`. The case-sensitive literal search scans stored worksheet text and formula text, including hidden sheets and sparse cells; results contain cell addresses and bounded excerpts. `--sheet` or `sheet` restricts the search to one named worksheet. Each page scans at most 100,000 stored cells and returns at most 200 matches. When `next_offset` is present, continue with that offset and the returned `snapshot_sha256`, keeping the query and sheet unchanged; the CLI options are `--offset` and `--snapshot-sha256`. A changed snapshot is rejected. Counts and `scan_complete` describe the current page and its remaining scope; `complete` is true only for a fully verified search from offset zero. Check every page's `unverified_text_cells`: complex shared strings, Excel escapes, unsupported rich-text content and shared-formula followers can make coverage incomplete. Supported plain and rich shared strings are checked directly against the package XML; Excel escape syntax follows the considerations documented in [Microsoft’s ST_Xstring notes](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oe376/bd0aa042-434a-4ca7-b25f-4e1fd25a954d). Chart sheets, chart contents and calculated values are outside the search. Use `cells` to inspect a located range and check formula cache freshness separately. The operation copies the saved workbook and enforces the same package limits as the overview; later pages rescan preceding cells.

```

```

For tabular spreadsheet input, provide rectangular `ranges` keyed by worksheet:

```json
{"ranges":{"Sales":[{"start":"A1","values":[["Quarter","Revenue"],["Q1",120],["Q2",140]]}]},"sheet_options":{"Sales":{"tables":[{"name":"SalesTable","range":"A1:B3"}]}}}
```

Each block takes a single-cell `start` and nonempty rectangular `values` rows. Values use the same types, formula behavior and explicit literal-text format as `sheets`. Different blocks and individually specified `sheets` cells must not overlap. Each block has at most 200 columns; a request can include up to 100 blocks per worksheet, 100 range worksheets and 100,000 range cells in total. Source-based writing uses the same table-header and totals protection as single-cell authoring. The spreadsheet library can alter unsupported features and caches when saving a source workbook; use targeted session editing when preserving those matters.

For spreadsheet cells that must remain literal text, use a typed value:

```json
{"sheets":{"Data":{"A1":{"type":"text","value":"=SUM(1,2)"},"A2":{"type":"text","value":"#N/A"},"A3":{"type":"text","value":"00123"},"B1":"=1+2"}}}
```

All authored spreadsheet text is checked before writing: text is limited to 32,767 UTF-16 units and formulas to 8,192 units, and unsupported XML characters are rejected. Numeric values must be finite and within the Excel numeric range. An empty formula (`=`) is rejected. Excel stores numeric values at floating-point precision; use explicit text when exact long identifiers matter. Typed text is saved as text even when it resembles a formula or Excel error. It must be nonempty, at most 32,767 UTF-16 units, and contain no unsupported XML controls, surrogate code points, noncharacters or Excel escape-like sequences. Use `null` for a blank cell. Untyped strings beginning with `=` retain formula behavior; `author` does not calculate formulas. Typed values work in new workbooks and source-based copies, subject to the same table-header and totals protections as other cell edits.

For new Word documents, optional `page_setup` configures page size, margins and running text:

```json
{"page_setup":{"size":"a4","orientation":"portrait","margins":{"top":0.8,"bottom":0.8,"left":0.9,"right":0.9},"header":{"text":"Quarterly report","align":"left"},"footer":{"text":"Page","align":"right","page_number":true}},"blocks":[{"type":"heading","text":"Overview"}]}
```

Sizes are `a4` and `letter`; orientation is `portrait` or `landscape`. Omitted size and margins retain document defaults. Margins are in inches (0–5), and must leave at least half an inch of content area in each dimension. Header and footer take single-line text of at most 1,000 characters and `left`, `center` or `right` alignment. `page_number` adds a Word PAGE field after footer text; the field holds a placeholder until a compatible application updates it. The setting applies to new single-section documents; source-based authoring rejects `page_setup`. Rendering and printer margins can affect placement.

Use typed values for native spreadsheet dates and date-times:

```json
{"ranges":{"Schedule":[{"start":"A1","values":[["Event","Date","Time"],["Launch",{"type":"date","value":"2026-10-31"},{"type":"datetime","value":"2026-10-31T09:30:45.125"}]]}]}}
```

Dates use `YYYY-MM-DD`; date-times use `YYYY-MM-DDTHH:MM:SS` with optional one-to-three fractional digits. Values have no time zone and are stored using the workbook's date system. Dates earlier than 1900-01-01 or on/before the workbook epoch are rejected; this excludes 1904-01-01 in a 1904-date-system workbook. A date-appropriate number format is applied when the cell has no date format; use `sheet_options.formats` to control display, including fractional seconds. Check formulas and application-specific date formatting after editing.

For ordered Word content, `author` and MCP `author_file` accept `blocks`:

```json
{"blocks":[
  {"type":"heading","level":1,"text":"Quarterly review"},
  {"type":"paragraph","align":"justify","space_after":8,"line_spacing":1.2,"runs":[{"text":"Revenue grew "},{"text":"18%","bold":true,"font":"Arial","font_size":14,"color":"236B8E"},{"text":" (source)","url":"https://example.com/report"}]},
  {"type":"bullet","text":"Retention remained stable."},
  {"type":"numbered","text":"Prioritize onboarding."},
  {"type":"table","header":true,"style":"Light Shading Accent 1","column_weights":[2,1],"header_fill":"236B8E","header_color":"FFFFFF","font":"Arial","font_size":10,"rows":[["Metric","Value"],["Retention","92%"]]},
  {"type":"image","path":"/absolute/path/to/figure.png","width":5.5,"align":"center","description":"Revenue trend"},
  {"type":"page_break"}
]}
```

Table cells can also contain multiple formatted paragraphs:

```json
{"blocks":[{"type":"table","header":true,"rows":[["Metric","Details"],["Growth",{"paragraphs":[{"runs":[{"text":"18%","bold":true,"color":"14804A"},{"text":" source","url":"https://example.com/source"}]},{"text":"Year over year","align":"right"}]}]]}]}
```

Each cell accepts plain text or an object with 1–20 `paragraphs`; each paragraph supplies `text` or `runs` and optional `align`. Runs use the same formatting and URL rules as text blocks. Table font, font size, and header formatting are defaults that individual runs can override. Hyperlinks default to blue and underlined. The document block limits also apply to rich table content.

Text blocks accept either `text` or `runs`, optional `align` (`left`, `center`, `right`, `justify`), `space_before` and `space_after` in points (0–400), `line_spacing` as a multiple (0.5–4), and boolean `keep_with_next`, `keep_together` and `page_break_before`. Runs accept boolean `bold`, `italic` and `underline`, `font` (up to 100 characters), `font_size` in points (1–400, in half-point increments), and six-digit RGB `color`. Font names are applied to Latin, East Asian and complex-script slots. A run may specify a `url` with an HTTP, HTTPS or mailto link; it is styled blue and underlined by default, and `color` and `underline` can override those choices. Image blocks embed a local PNG or JPEG at the required width in inches, keeping its pixel aspect ratio; they accept `align` (`left`, `center`, `right`) and an accessibility `description`. Each image is snapshotted and limited to 20 MiB and 40 million pixels, with at most 128 MiB of images per request. Width must be 0.1–22 inches and resulting height 0.01–22 inches; EXIF orientation must be normalized. Heading levels range from 1 to 9. A table's optional `header` bolds its first row and marks it as a repeating header; optional `style` must name a table style available in the document. `column_weights` sets fixed proportional column widths across the last section's page width minus margins; provide one weight from 0.01 to 1,000 per column. `header_fill` and `header_color` are six-digit RGB and require `header: true`. `font` and half-point `font_size` apply to all table cells. Column layouts, table indents and rendered wrapping can affect the result; inspect the output. Lists use the document's `List Bullet` and `List Number` styles. Blocks follow any legacy `paragraphs` entries and, with a source, are appended after existing content. Limits are 200 blocks, 200 runs per text block, 100 rows and 20 columns per table, 2,000 cells per table, 10,000 characters per run or cell, and 2,000,000 serialized characters for all blocks. Render and inspect the resulting document in the target application.

For basic Excel authoring, `sheet_options` can format a workbook in the same request:

```json
{"sheets":{"Forecast":{"A1":"Quarter","B1":"Revenue","A2":"Q1","B2":100,"A3":"Q2","B3":"=B2*1.2"}},
 "sheet_options":{"Forecast":{"freeze_panes":"B2","auto_filter":"A1:B3","column_widths":{"A":18,"B":20},"row_heights":{"1":24},
   "formats":[{"range":"A1:B1","bold":true,"fill":"236B8E","font_color":"FFFFFF","horizontal":"center"},
              {"range":"B2:B3","number_format":"#,##0.00"}]}}}
```

Options apply to existing worksheets after values are written. Freeze panes accepts a single cell or `null`; auto-filter accepts a range of at most 10,000,000 cells or `null` and rejects replacement when existing filter criteria or sort state are present. Column widths use Excel character units (greater than 0 and at most 255); row heights use points (greater than 0 and at most 409.5). Format entries accept `bold`, `italic`, `font_size`, six-digit RGB `font_color` and `fill`, `number_format`, `horizontal` (`general`, `left`, `center`, `right`) and boolean `wrap`. Omitted properties retain their existing direct settings. Each format covers up to 10,000 cells; all formats together cover up to 20,000 cells, with at most 100 format entries per sheet and 200 dimension entries of each kind. Merged-cell placeholders are rejected. Formulas are stored without calculation; formula caches may be missing and LibreOffice previews may recalculate them. When modifying an existing workbook, library round-tripping can change unsupported features and formula caches; use the targeted session grid when preserving those matters.

Create native conditional formats with `conditional_formats` in `sheet_options`:

```json
{"sheets":{"Data":{"A1":-10,"A2":5,"A3":30}},"sheet_options":{"Data":{"conditional_formats":[{"type":"cell","range":"A1:A3","operator":"lessThan","values":[0],"fill":"FFC7CE"},{"type":"color_scale","range":"B1:B3","min_color":"F8696B","mid_color":"FFEB84","max_color":"63BE7B"},{"type":"data_bar","range":"C1:C3","color":"638EC6"},{"type":"formula","range":"D1:D3","formula":"=A1>20","fill":"C6EFCE"}]}}}
```

Cell rules accept numeric `values` and `equal`, `notEqual`, `lessThan`, `lessThanOrEqual`, `greaterThan`, `greaterThanOrEqual`, `between` or `notBetween`; the last two take two ordered values. Formula rules store an Excel formula with an optional leading `=`; syntax and results require review in a spreadsheet application. Cell and formula rules accept `stop_if_true`. Color scales use minimum and maximum values, with an optional 50th-percentile midpoint. Data bars use the range minimum and maximum and display cell values. Colors are six-digit RGB. Rules are appended after existing priorities; ambiguous existing priorities are rejected. Each rule covers at most 1,000,000 cells and each sheet accepts up to 100 added rules. The saved workbook carries the rules, which are evaluated by the spreadsheet application. Source-based authoring uses an openpyxl round trip and can change unsupported features or caches.

Create spreadsheet dropdowns using `list_validations` in `sheet_options`:

```json
{"sheets":{"Data":{"A1":"Low","A2":"High"}},"sheet_options":{"Data":{"list_validations":[{"range":"B1:B100","values":["Low","Medium","High"]},{"range":"C1:C100","source":"A1:A2","allow_blank":true}]}}}
```

Each entry specifies one target range and either a literal `values` list or a one-dimensional `source` range on the same worksheet. Literal lists are limited to 255 UTF-16 units including separators and quotes; commas, double quotes, control characters and Excel escape sequences are rejected. Source ranges contain at most 100 cells. Each target covers at most 1,000,000 cells; up to 100 rules per worksheet are accepted. Overlap with existing validation rules is rejected. The dropdown is visible and Excel is instructed to reject invalid entries; `allow_blank` defaults to false. The local grid exposes suggestions for supported lists but does not enforce validation when editing. Source-based authoring uses an openpyxl round trip and can change unsupported features or caches.

Create a native Excel table with `tables` in `sheet_options`:

```json
{"sheets":{"Sales":{"A1":"Quarter","B1":"Revenue","A2":"Q1","B2":120,"A3":"Q2","B3":140}},"sheet_options":{"Sales":{"tables":[{"name":"SalesTable","range":"A1:B3","style":"TableStyleMedium2","row_stripes":true}]}}}
```

Each table requires a workbook-unique name, a rectangular range with a header and at least one data row, and unique nonempty literal text headers. Names use ASCII letters, digits, underscores and periods, start with a letter or underscore, and cannot be cell references. Built-in `TableStyleLight1`–`21`, `TableStyleMedium1`–`28`, and `TableStyleDark1`–`11` are supported. Boolean `row_stripes`, `column_stripes`, `first_column` and `last_column` control style flags. Tables may not overlap merged cells, other tables or the sheet auto-filter. Limits are 1,000,000 cells per range, 20 tables per sheet and 100 per request. Source-based cell authoring, targeted grid editing and text replacement protect table header and totals cells; use the supported table-column rename operation for header changes. Ordinary data cells remain editable. Generic OfficeCLI operations can change table structures and require independent review. Source-based authoring can alter unsupported workbook features and caches.

For a supported table, rename a column in a new revision with `office-use session rename-table-column ./draft --base 0 --sheet Sales --table SalesTable --old Revenue --new 'Net Revenue'`, or MCP `session_rename_table_column`. It updates the header cell and table metadata together and rewrites explicit `SalesTable[Revenue]` and nested `SalesTable[[#All],[Revenue]]` references in worksheet formulas, conditional formatting, data validation, defined names and chart formulas. Implicit references such as `[@Revenue]` are resolved in uniquely owned table cells and calculated-column or totals-row formula metadata; references belonging to other tables are preserved. It clears the cached results of rewritten worksheet formulas, requests recalculation and removes a supported calculation chain. `rewritten_references` reports the number of substitutions; the original revision remains available. Shared and array formulas, implicit references without a uniquely identified table, unsupported table-column metadata, escaped column names, indirect formulas, brackets outside supported formulas, rich-text target headers, active filter criteria, linked table columns and opaque dependencies are rejected. Inspection covers at most 1,000 workbook XML parts, 8 MiB per part, 100 changed parts and 500 rewritten references. Other formula and chart caches may become stale; calculation mode is preserved, including manual mode. Recalculate or synchronize as appropriate and review in the target application.

Add a local image as an editable worksheet drawing with `images` in `sheet_options`:

```json
{"sheets":{"Report":{"A1":"Revenue"}},"sheet_options":{"Report":{"images":[{"path":"/absolute/path/to/figure.png","anchor":"C3","width":320,"description":"Revenue trend"}]}}}
```

The image is snapshotted and embedded. PNG and JPEG are supported; `anchor` is a single cell and `width` is 1–4,096 pixels at 96 DPI. Height follows the pixel aspect ratio and must also be 1–4,096 pixels; EXIF orientation must be normalized. `description` supplies accessible alternative text up to 1,000 characters. Each image is limited to 20 MiB and 40 million pixels, with at most 20 images per sheet, 50 per request and 128 MiB across the request. The completed workbook is limited to 5,000 parts and 128 MiB both on disk and uncompressed. Spreadsheet rendering and print areas can affect visibility. Source-based authoring uses an openpyxl round trip, which can change unsupported workbook features and caches.

For a printable worksheet, set `print_options` within the relevant `sheet_options`:

```json
{"sheets":{"Data":{"A1":"Metric","B1":"Value","A2":"Revenue","B2":120}},"sheet_options":{"Data":{"print_options":{"paper":"a4","orientation":"landscape","area":"A1:B2","repeat_rows":"1:1","repeat_columns":"A:A","header":{"text":"Quarterly report","align":"left"},"footer":{"text":"Page","align":"right","page_number":true}}}}}
```

`paper` is `a4` or `letter`; orientation is `portrait` or `landscape`. `area` is a single cell range with at most 10,000,000 cells; `repeat_rows` and `repeat_columns` accept ranges such as `1:2` and `A:B`. Set these fields to `null` to clear them. `margins` accepts `left`, `right`, `top`, `bottom`, `header` and `footer` in inches (0–5). Header and footer write the specified `left`, `center` or `right` slot; existing other slots remain. A footer may include `page_number: true`. Text is literal, including ampersands, and the complete header or footer is limited to 255 UTF-16 code units. These settings apply to default/odd-page headers and footers; existing first/even-page settings are preserved. Small margins can suppress running text in LibreOffice or on printers, so inspect every rendered page. Source-based workbook authoring can alter unsupported workbook features and caches.

The same `sheet_options` can create editable column or line charts:

```json
{"sheets":{"Sales":{"A1":"Quarter","B1":"Revenue","A2":"Q1","B2":100,"A3":"Q2","B3":120}},
 "sheet_options":{"Sales":{"fit_to_page":true,"charts":[{"type":"column","data":"B1:B3","categories":"A2:A3","anchor":"D2","title":"Revenue","width":14,"height":8}]}}}
```

`data` is a rectangular range on the same sheet, with one series per column. `titles_from_data` defaults to `true` and uses the first row as series titles; set it to `false` when the range contains only data. Optional `categories` must be one column matching the data rows. Literal text and numeric categories are detected automatically; use `category_type: "text"` or `"number"` for mixed or formula categories. Chart `width` and `height` are in centimeters; `anchor` is a cell. Optional titles are `title`, `x_axis_title` and `y_axis_title`. Up to 20 charts per worksheet, 30 series per chart and 10,000 cells per source range are supported. Chart values reference cells and may include formulas; inspect the data types and result. `fit_to_page: true` sets one page wide with unlimited height; it can reduce legibility, so review the PDF. The basic writer populates chart caches for nonempty literal text and finite numeric source cells; formula, blank, ambiguous and oversized sources retain missing caches. Each cached reference is limited to 2,000 points and 1,000 characters per text point, with at most 50,000 points and 8 MiB of values across the request. Formula caches are not calculated. Use `scan-chart-caches`, recalculate with a compatible application when needed, and review the result in the target application. Existing-workbook saves can alter unsupported features and caches.

PowerPoint authoring also supports positioned elements and a custom slide size for new files:

```json
{"slide_size":{"width":13.333,"height":7.5},"slides":[{"layout":"blank","background":"F5F8FC","notes":"Discuss the quarterly trend.\nHighlight the next steps.","elements":[
  {"type":"textbox","x":1,"y":0.7,"width":10,"height":1,"text":"Quarterly review","font_size":32,"font":"Arial","bold":true,"color":"14283F"},
  {"type":"rectangle","x":1,"y":2,"width":2,"height":0.1,"fill":"236B8E"},
  {"type":"table","x":1,"y":3,"width":7,"height":1.5,"rows":[["Metric","Value"],["Growth","18%"]],"header":true,"font_size":18,"header_fill":"236B8E","header_color":"FFFFFF","column_weights":[2,1]},
  {"type":"image","x":9,"y":2,"width":3,"height":2,"path":"/absolute/path/to/image.png","description":"Illustration","fit":"contain"},
  {"type":"chart","chart_type":"column","x":1,"y":5,"width":7,"height":2,"title":"Revenue","categories":["Q1","Q2"],"series":[{"name":"Revenue","values":[100,120],"color":"236B8E"}]}
]}]}
```


Each new slide can include a `notes` string for its editable speaker-notes body. Newlines create separate paragraphs; tabs are preserved. Notes may contain up to 100,000 characters, with control characters other than newline and tab rejected. Omitting `notes` leaves the new slide without a notes slide; an empty string creates an empty notes body. Notes are available through the existing notes read, search and session edit operations. Source-based authoring appends slides and uses a PowerPoint library round trip, so inspect existing presentation features after saving.

For rich slide text, use `paragraphs` instead of `text` on a textbox:

```json
{"type":"textbox","x":1,"y":1,"width":8,"height":3,"font":"Arial","font_size":24,"paragraphs":[{"runs":[{"text":"Revenue "},{"text":"+18%","bold":true,"color":"236B8E"}]},{"text":"Retention 92%","bullet":true},{"text":"Renewals improved","bullet":true,"level":1}]}
```

Each paragraph takes `text` or `runs`, optional `align`, boolean `bullet`, `level` (0–8) and `space_after` in points (0–400). Runs support `font`, `font_size`, `color`, boolean `bold`, `italic`, `underline` and HTTP(S)/mailto `url`; run settings override textbox defaults. Use separate paragraphs for line breaks. Limits are 100 paragraphs per textbox, 100 runs per paragraph and 10,000 characters per run, within the slide request limit. Inspect rendering and links in the destination application.

PowerPoint table cells can use the same paragraph and run format:

```json
{"type":"table","x":1,"y":1,"width":8,"height":2,"header":true,"rows":[["Metric","Details"],["Growth",{"paragraphs":[{"runs":[{"text":"18%","bold":true,"color":"14804A"},{"text":" source","url":"https://example.com/source"}]},{"text":"Year over year","align":"right"}]}]]}
```

A cell accepts a plain string or an object with `paragraphs`. Rich paragraphs use the textbox paragraph and run properties and limits. Table font, size, text color and header styling act as defaults; run properties can override them. Use paragraph-specific paths when editing a cell with multiple paragraphs. Check text fitting and layout in the target application.

Geometry and slide size are in inches. Textboxes accept either `text` or `paragraphs`, plus defaults for `font_size` in points, `font`, `color`, `bold`, `italic`, `align` (`left`, `center`, `right`) and `fill`; optional `margins` set `left`, `right`, `top` and `bottom` in inches (0–5), `vertical_align` selects `top`, `middle` or `bottom`, `wrap` is boolean, and `auto_fit` selects `none`, `shrink` or `resize`. Margins must leave a positive text area. `shrink` asks the rendering application to fit text inside the shape; `resize` asks it to expand the shape. Applications may interpret these settings differently, so inspect the rendered slide. The rendered-text checker uses saved shape bounds and may flag text displayed beyond them. Colors are six hexadecimal RGB digits. Rectangle `fill` is required. Editable table elements accept rectangular `rows` of strings or rich paragraph objects, an optional boolean `header`, `font_size`, `font`, `color`, `header_fill`, `header_color`, and relative `column_weights`; header colors require `header: true`. A table is limited to 50 rows, 20 columns, 500 cells and 10,000 characters per plain-text cell or rich run. Chart elements support `chart_type` of `column` or `line`, nonempty text `categories`, and named numeric `series`; each series may set an RGB `color` and `number_format`, and `null` represents a missing point. Optional `title`, `x_axis_title`, `y_axis_title` and boolean `legend` control presentation. Charts include embedded XLSX data and chart caches; a post-write check rejects labels interpreted as spreadsheet formulas or links and numeric values that cannot be preserved. Limits are 200 categories, 20 series and 2,000 points per chart, and 20 charts and 10,000 points per request. Existing embedded chart data can be edited through a session grid; inspect and synchronize chart caches after editing. Images must be local PNG or JPEG, at most 20 MiB and 40 million pixels each, with at most 128 MiB across the request; each image is snapshotted, embedded and can carry a `description` for accessibility. `fit` may be `stretch` (default), `contain` (centered within the rectangle with its aspect ratio preserved) or `cover` (aspect-preserving centered crop in the full rectangle). Contain and cover require an image with normalized EXIF orientation. Extremely disproportionate cover crops are rejected. Slides and elements preserve input order. A blank slide requires a uniquely named `Blank` layout in the source or default template. Without `layout`, the existing `title`/`body` layout is used. `slide_size` is available when creating a new deck and defaults to the template's size if omitted. The source template's themes can affect rendered shapes and text. Limits are 100 slides, 200 elements per slide and 2,000,000 serialized characters for the slide list; inspect rendered pages and layout candidates.

The `author` command sets whole paragraphs, cells or text frames. Replacing paragraph or shape text drops its run-level formatting. The libraries may alter or drop unsupported Office features when saving existing files; retain the original and review the output. Formula strings are stored, not recalculated by `author`. LibreOffice rendering may recalculate and can differ visually from Microsoft Office. Inspect is a basic content extraction and is not a full fidelity representation (e.g. charts, text in DOCX tables during paragraph edits, speaker notes, and embedded objects). Rendering produces PDF; use a PDF viewer to inspect pages visually. The `author` command does not support encrypted or macro-enabled files, live editing, collaboration, comments, tracked changes, cloud documents, or advanced styling beyond the documented basic authoring properties.

Authoring from a source, structured renders, page previews, selection extraction, Word/slide/cell searches, Word tracked-change inspection, review bundles, OfficeCLI batches, session startup, restore and export check the source file identity, size and timestamps while making their snapshot; detected concurrent changes fail with a retry message. The check depends on filesystem metadata and does not lock other writers. Other inspection operations may use separate snapshot copying; use a saved, closed file for reliable results.

## External relationships

Use `office-use external-links file.docx`, `office-use session external-links ./draft --revision 0`, or MCP `inspect_external_relationships` / `session_inspect_external_relationships` to inventory OPC relationships marked external in a saved snapshot. The review bundle includes the same check and flags external relationships or incomplete coverage. Results report relationship parts, IDs, types and targets; no target is contacted. The inventory scans at most 100,000 relationships, returns up to 200 external relationships and clips individual fields at 1,000 characters. Check `complete`, `truncated`, `fields_truncated` and `issues` before relying on the list. Excel formulas, Word field codes, embedded Office documents and other indirect references are outside this scan. Targets can contain private paths or credentials; treat output and review bundles as sensitive.

## Structured OfficeCLI operations

OfficeCLI provides element paths, queries, formatting, charts, images and other operations. Its full command and property schema is available through `officecli help`. `structured` returns the OfficeCLI JSON data for an outline, element, or query:

```sh
office-use schema xlsx --operation add --query chart
office-use schema xlsx --element chart --operation add --query datarange
office-use structured input.docx outline
office-use structured input.docx get '/body/p[1]'
office-use structured input.docx query 'paragraph'
```

`office-use schema` and MCP `office_schema` query the locally installed OfficeCLI version. Without `--element`, they list matching elements and paths; with an element they return its operations, property definitions, aliases and examples. The query matches element names and paths in a catalog, or property names, aliases and descriptions in an element schema. For `add`, `set` and `get`, property results are filtered by the operation; `query` and `remove` filter element availability while returning the matching property descriptions. The returned version identifies the schema source. OfficeCLI schemas describe the installed executable; validate and visually inspect authored files.

`batch` creates a new file or applies an OfficeCLI JSON batch to a copy:

```json
[{"command":"add","parent":"/body","type":"paragraph","props":{"text":"Executive summary","bold":"true"}}]
```

```sh
office-use batch --spec operations.json --out new.docx
office-use batch --source original.docx --spec operations.json --out revised.docx
```

For example, an XLSX chart can be added to a workbook whose `Sales` sheet contains category and value columns in `A1:B3`:

```json
[{"command":"add","parent":"/Sales","type":"chart","props":{"chartType":"column","dataRange":"Sales!A1:B3","title":"Revenue","anchor":"D2:J15"}}]
```

Save that array as `chart.json` and call `office-use batch --source sales.xlsx --spec chart.json --out charted.xlsx`, or pass it to MCP `session_apply` for a new session revision. Check the installed chart schema, source ranges, rendered output and chart caches before delivery.

To extract a starting batch from a saved document or a session revision:

```sh
office-use dump input.docx '/body/p[1]' | jq '.operations' > paragraph-ops.json
office-use session dump ./draft --revision 1 --path '/slide[1]'
```

MCP offers `dump_office_subtree` and `session_dump_office_subtree`. The result includes the snapshot SHA-256 and OfficeCLI's operation array, including its `meta` item; inspect the paths and operations before passing them to `batch` or `session_apply`. Paths may target existing content. Subtrees can depend on styles, numbering, themes, masters or layouts from sibling parts. OfficeCLI 1.0.147 was observed omitting charts from an XLSX sheet dump, and a slide dump using a numeric layout required a compatible target template. Compare source and replayed structure and render the result before delivery. Dumps are limited to 1 MiB of JSON and 1,000 operations; larger results are rejected without returning a partial batch. Source and extracted operations can contain sensitive document content.

For XLSX operations handled by OfficeCLI, formula caches can be updated even when the requested operation changes only formatting. `resize-grid` edits worksheet dimensions directly, `format-grid` merges verified styles, and `edit-grid` and XLSX `session_edit` merge supported target values into the original package; these operations retain unrelated formula caches. Batch results expose `formula_cache_effect: "may_change"`; compare relevant formulas and cached values and review calculation compatibility before delivery.

Operations run on a temporary file. A successful batch is closed before the complete result is published to a new path; errors leave the requested output absent. Existing outputs are never replaced. This publication uses a hard link on the destination filesystem; filesystems that do not support hard links return an error. Use a saved and closed source file: edits held in another OfficeCLI resident session are not included in the disk copy. Only the tested OfficeCLI version is known to work; its operation schemas and rendering fidelity must be checked against the target version and documents. These commands use the separately installed OfficeCLI executable; it is not bundled.

`preview` creates a new directory containing one PNG per rendered page. It refuses an existing directory. For a numbered overview of up to 12 pages, use `office-use contact-sheet slides.pptx --out overview.png --start 1 --count 12`; choose another start page to continue. The equivalent MCP tools are `view_contact_sheet` for a saved file and `session_contact_sheet` for a specific revision. Each returns a native PNG image, with the rendered page range and total in the header. These page numbers refer to LibreOffice's PDF output; hidden slides can change the mapping to PowerPoint slide numbers. Inspect full-size page images for small text and details, since an overview, successful render, or schema validation alone does not establish visual quality or Office fidelity.

To inspect one rendered page without producing all page PNGs, use `office-use render-page slides.pptx --page 2 --out page-2.png`. Add `--box 0 0 1 0.5` to crop to the top half; coordinates are normalized left, top, right, bottom from the top-left. MCP `view_document_page` and `session_view_page` return the page or crop as a native image, with an explicit session revision for the latter. Whole-page images have a maximum dimension of 1,800 pixels. Crops are rendered again at up to a 7,200-pixel full-page scale, targeting a 1,800-pixel maximum crop dimension; coordinates are rounded to raster pixels. Very small regions or low-resolution embedded images may need another source. Outputs are limited to 10 MiB and existing PNG files are protected.

## Multi-step draft sessions

A session is a local directory of saved revision files. Start from a saved source, or pass `--format docx`, `xlsx` or `pptx` to start blank. The directory must be new and its parent must exist.

For an existing source, startup limits the file to 128 MiB and checks the copied snapshot for ZIP packaging, required package metadata and a main content type matching its extension. This is a basic format check; use `audit` and visual review to assess document validity and fidelity. If startup fails, the new session directory is removed.

```sh
office-use session start ./draft --source original.docx
office-use session info ./draft
# Replace one match in a simple Word body paragraph, creating revision 1
office-use session replace-text ./draft --base 0 --path '/body/p[1]' --find 'old text' --replace 'new text'
office-use session apply ./draft --base 1 --spec operations.json
office-use session restore ./draft --base 2 --revision 0
office-use session export ./draft --revision 3 --out final.docx
```

For several targeted changes, `office-use session replace-text-batch ./draft --base 0 --changes '[{"path":"/body/p[1]","find":"old","replacement":"new"},{"path":"/body/p[2]","find":"before","replacement":"after"}]'` and MCP `session_replace_text_batch` apply 1–25 replacements in the supplied order and publish one revision only after all succeed. Each step uses the same format-specific validation and formatting preservation as `replace-text`; later steps see earlier changes. If a step fails or a concurrent edit wins, no batch revision is published. For XLSX, results request recalculation and report potentially stale formula caches. Search and inspect each target first; the operation is an explicit list of changes.

`replace-text` and MCP `session_replace_text` find exactly one literal match in a Word body, header or footer paragraph, including matches spanning multiple text runs. Replacement text uses the first matched run's formatting; other runs and all other package parts remain intact. It preserves ordinary hyperlinks, bookmarks and comment anchors when the match stays within one region. Matches crossing a hyperlink or anchor boundary are rejected. Ambiguous matches, signed documents, control characters, fields, tracked changes and other unsupported structures are also rejected. Paths use one-based physical table, row, cell and paragraph indices, including nested tables. A paragraph may also be addressed by its saved `paraId`; duplicate IDs within its container are rejected. `session_edit_target` exposes `replace_text_path_supported` for path eligibility; actual paragraph structure is checked when applying the replacement. Packages are limited to 5,000 parts and 128 MiB. The edited XML part is reserialized, so visually review the result.

List header and footer paragraphs with `office-use stories input.docx`, `office-use session stories ./draft --revision 0`, MCP `list_word_stories` or `session_list_word_stories`, or the viewer's “Word headers and footers” panel. These paths use relationship IDs, for example `/header[@id=rId9]/p[1]`, and are distinct from OfficeCLI's numbered header paths. `references` identifies explicit section references; `linked_sections` traces each default, first and even reference through subsequent sections, and `same_part_ids` identifies other relationships pointing to the same part. Check all such IDs before editing: changes affect every section using the part. First and even page variants depend on document settings, section properties and pagination; links describe references, while actual display requires visual review. Word's default header inheritance behavior is described in the [Microsoft interoperability notes](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-oi29500/5de15e59-3ec1-4f80-aa4d-00bdd447b86f).

`reference_resolution_complete: false` indicates unsupported section locations or a limit: at most 5,000 sections and 2,000 linked section entries are resolved. Documents with more than 200 header/footer relationships are rejected by the inventory. Inventory text concatenates Word text nodes and can omit fields or other content. It lists at most 200 paragraphs and 4,000 characters each; `complete` and per-paragraph `truncated` identify limitations. Unsupported wrappers or excessive nesting make the paragraph inventory incomplete. The viewer offers text replacement for listed paragraphs; header and footer comments are not supported.

For a loaded header or footer paragraph, `session_edit_target` returns `story_impact` with linked sections from every relationship pointing to that part, alongside its completeness flag. The viewer shows the same impact before replacement.

For PPTX sessions, `replace-text` and `session_replace_text` also accept paths such as `/slide[1]/shape[1]/paragraph[1]` or `/slide[1]/shape[@id=2]/paragraph[1]`. Slides follow the presentation order, even when package part names have been reordered; a slide part referenced by multiple slide entries is rejected. Shape and group indices each count their own element type; shape IDs from structured reads are also accepted. Nested group paths are supported through CLI and MCP. A shape path without a paragraph is accepted only for a single-paragraph text body. Replacement uses the first matched run's formatting and preserves the other package parts. Table-cell paths such as `/slide[1]/table[1]/tr[1]/tc[1]/paragraph[1]` use one-based physical row and cell indices; merged-cell placeholders are rejected and the merged origin can be edited. Select a paragraph explicitly when a cell or shape contains more than one. The viewer loads supported table cells read-only and offers paragraph-based replacement. Paragraphs containing line breaks, fields or run hyperlinks, and shape containers with alternate content, are rejected; charts and notes require other workflows. The viewer offers this operation for supported targets that OfficeCLI can load. Review the rendered output.


Add a Word review comment to a simple nonempty body or table-cell paragraph with `office-use session add-comment ./draft --base 0 --path '/body/p[1]' --author 'Reviewer' --text 'Please review'`. MCP `session_add_comment` and the viewer's element editor provide the same operation. It adds a new revision and returns the comment ID. By default it anchors the whole paragraph; pass `--anchor "exact phrase"`, the MCP `anchor` argument, or the viewer’s anchor field to select one unique literal phrase within adjacent text runs. Splitting runs preserves their text and formatting. Literal matching rejects repeated or missing phrases and ranges that cross or lie within hyperlink or annotation boundaries. With an explicit anchor, separate links and existing anchors elsewhere in the paragraph are retained. Whole-paragraph comments require a simple paragraph. Fields, tabs, tracked structures, unsafe run identities, and digitally signed packages are rejected. The operation accepts plain-text comments up to 4,000 characters. When extended comment metadata already exists, new root comments receive matching thread, paragraph and, where present, durable-ID and extensible records; duplicate, malformed or unlinked metadata is rejected. Legacy documents keep their existing metadata model. Mention and application-identity metadata are not generated.

Reply to an open root comment using `office-use session reply-comment ./draft --base 1 --parent-id 0 --author 'Editor' --text 'Acknowledged'`, MCP `session_reply_comment`, or the viewer's comment list. The reply inherits the root comment's exact main-body anchor and creates a new revision. The parent must appear among the first 200 comments, have one complete ordered body anchor whose range markers are direct paragraph children, and have an unambiguous open root-thread state. Reopen a resolved thread first. Legacy threads receive Word 2013 metadata when needed. When a document has a uniquely mapped `commentsIds` part, the reply receives a distinct durable ID; an existing `commentsExtensible` part also receives the matching UTC record. The operation rejects unlinked, incomplete, malformed or ambiguous modern metadata, including an extensible part without IDs. Mentions and application identity metadata are not generated. See the [Word comment ID](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-docx/9c360cd7-653f-4d82-82be-7bda2488c0c1) and [extensible comment](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-docx/a7b57225-42e5-43e7-8d98-d90eabf3ca25) specifications. Replies to replies are not supported. Review the result in Word; native Word interoperability has not yet been tested.

Resolve or reopen a root comment with `office-use session resolve-comment ./draft --base 1 --id 0 --resolved true` (use `false` to reopen), MCP `session_resolve_comment`, or the comment list in the latest viewer revision. This creates a new revision. For a legacy comment with a complete main-document anchor, the operation adds Word 2013 extended metadata and, if needed, a unique paragraph ID. If an extended record already exists, it must identify a unique root comment. A legacy anchored comment with no extended record can receive one when newer comment-ID and extensible metadata are absent. Ambiguous or malformed mappings, replies and unsupported modern metadata are rejected. Other comment parts are preserved. Review the resulting file in Word; native Word interoperability has not yet been tested.

Read saved comments with `office-use comments file.docx` or `office-use session comments ./draft --revision 1`. MCP offers `list_word_comments` and `session_list_comments`; the viewer can load comments for the displayed revision. The result includes the first 200 comments, author, date, plain-text body and main-document anchor hints, with truncation and scan-completeness flags. Paragraph paths cover supported body and table structures; fields, deleted content, drawings and other complex content can make extracted anchor text incomplete. Anchors outside the main body, unsupported wrappers and malformed or partial ranges may lack a usable path. When a valid Word 2013 `commentsExtended` relationship maps a comment by the final paragraph’s `w14:paraId`, `resolved` and reply parent IDs are exposed. Missing, invalid, duplicate or unlinked metadata remains unknown and is identified by the metadata status fields; parent IDs may refer to comments outside the first 200 returned items. Other modern comment extensions are not interpreted. The mapping follows [Microsoft’s CT_CommentEx specification](https://learn.microsoft.com/en-us/openspecs/office_standards/ms-docx/9660dacc-2ceb-4352-87d2-42ba1184f522). Comment text is limited to 4,000 characters per item, anchor text to 2,000 characters and paths to 20 per item. Inspect the original document for full review context.

Inspect existing Word revisions with `office-use tracked-changes file.docx`, `office-use session tracked-changes ./draft --revision 1`, or MCP `list_word_tracked_changes` / `session_list_word_tracked_changes`. The result includes a snapshot hash, the saved tracking setting when known, and a bounded inventory of common insertion, deletion, move, range-marker and formatting-change XML elements from the main document and related headers, footers, footnotes and endnotes. Entries include their type, parent, author, date, XML path hint and bounded text. A paragraph-mark deletion or formatting revision can have no text; XML elements do not map one-to-one to the revisions shown by Word. See [Microsoft's tracked-revision examples](https://learn.microsoft.com/en-us/office/open-xml/word/how-to-accept-all-revisions-in-a-word-processing-document). Check `scan_complete`, `issues` and `records_truncated`: at most 1,000 relevant relationships, 200 parts and 10,000 records are scanned, and the first 200 records are returned. Comments, other package parts, unsupported revision types, field semantics and full formatting diffs are outside this inventory. XML paths are inspection hints, not editable element paths. The viewer’s “Word tracked changes” panel inspects its displayed revision. Report contents can include sensitive text and author metadata.

To insert tracked text adjacent to an existing unique anchor, use `office-use session track-insert-text ./draft --base 0 --path '/body/p[1]' --anchor 'existing' --text 'new ' --position before --author 'Editor'`, or MCP `session_track_insert_text`. The viewer provides Insert before and Insert after alongside tracked replacement; Find supplies the anchor and Replacement supplies the new text. The result includes the insertion revision ID for later acceptance or rejection. The inserted run inherits formatting from the first anchor run for before, or the last for after. The same supported body, header and footer paths, range safeguards, and package restrictions as tracked replacement apply. The returned part and ID identify the insertion for later resolution. Inspect the resulting revision in Word.

To propose a tracked Word text replacement, run `office-use session track-replace-text ./draft --base 0 --path '/body/p[1]' --find 'old' --replace 'new' --author 'Editor'`, or call MCP `session_track_replace_text`. The viewer offers “Track replacement” after loading a supported body, header or footer paragraph. Review the displayed linked-section impact before editing a header or footer, since all sections referencing that part share the change. A unique literal match becomes a deletion record and, when replacement is nonempty, an insertion record in a new revision; deleted text retains its original run formatting, and the inserted text uses the first matched run's formatting. A match can span adjacent runs, but cannot cross hyperlink or annotation boundaries. Paragraphs containing existing tracked content, fields or unsupported structures are rejected. Targets inside tracked move or custom XML ranges, tracked paragraph or table structures, and parts with ambiguous or unmatched range markers are also rejected. The operation does not change the document's tracking setting; an empty replacement creates a deletion only. The original revision remains available. IDs are chosen after checking Word XML parts; signed packages are rejected. Inspect the resulting revision and review it in Word; native Word interoperability has not been tested.

To accept or reject selected simple Word insertion/deletion run records, use `office-use session resolve-tracked-runs ./draft --base 1 --part word/document.xml --id 12 --id 13 --decision accept`, or MCP `session_resolve_tracked_runs` with the part and IDs from a fresh tracked-change inventory. Use `reject` or `accept: false` to restore deleted runs and discard inserted runs. The viewer permits selecting candidate records and applying one decision within one part; backend validation determines whether each can be resolved. All selected records are validated before a new revision is published; earlier revisions remain available. A shared header or footer part can affect multiple sections. IDs must be unique and identify direct paragraph runs with supported content. Moves, tracked structural or formatting changes, nested revisions, complex run contents, selections inside tracked move or custom XML ranges, and parts with ambiguous or unmatched tracked ranges are rejected. Paired range markers elsewhere in the same story are preserved; move pairing and full revision validity are not assessed. These operations preserve the remaining package parts and reserialize the edited part. Review the result in Word; native Word interoperability has not been tested.

For an embedded PowerPoint picture, use `office-use session replace-picture ./draft --base 0 --path '/slide[1]/picture[@id=2]' --image replacement.png`, or MCP `session_replace_picture` with a local image file. In the viewer, select a picture, choose its geometric candidate, and upload a replacement. Static PNG and JPEG images are accepted up to 10 MiB and 40 megapixels. The operation creates a new revision and retains the picture's position, size, rotation, crop, and other slide properties; a new media relationship keeps other pictures using the original image unchanged. Linked images, animated images, pictures with unsupported blip extensions or effects, and digitally signed packages are rejected. Existing crop can change how the replacement appears; inspect the rendered revision. The original media remains in the package.

For XLSX sessions, `replace-text` and `session_replace_text` also accept a text cell path such as `/Sales Data/A1`. Inline and shared rich-text runs retain their formatting. Plain `str` cells without a formula are supported, including text written by the grid editor. Shared strings are reused when equivalent or added as a new entry, leaving other cells that referenced the original unchanged. Cell styles, hyperlinks, ordinary comments and unrelated package parts are retained. Formula cells, array/data-table/shared formula ranges, merged-cell placeholders, phonetic content, unsupported metadata and Excel escaped-text sequences are rejected. Formula caches elsewhere are left unchanged and can become stale after editing; use the calculation and review workflow when needed. After a successful text replacement, the edited worksheet records `sheetCalcPr/fullCalcOnLoad=1`, and the result reports `formula_cache_effect: "may_be_stale"` and `recalculation_requested: true`. Existing formula caches are retained until an application recalculates them; workbook calculation mode remains unchanged. The flag requests a full calculation on load, subject to the target application's behavior. See [Microsoft's sheet calculation properties](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.spreadsheet.sheetcalculationproperties).


Each successful batch creates the next revision. `--base` must match the latest revision; a stale or concurrent competing write fails. A failed batch leaves the previous revision intact. Restoring a historical revision creates a new latest revision; it uses the same base-revision conflict check and keeps all earlier versions. `info` lists file paths for use with `structured`, `compare`, `audit` and `preview`. Export copies any revision to a new output outside the session directory. Session operations never replace the source or an existing export. Keep the session directory private to its owner and do not edit its revision files directly: the session protocol assumes those files remain unchanged. Save and close external editing sessions before creating a session from a source. Session history persists until the directory is removed manually.

To watch the latest revision in a browser, run this in a separate terminal:

```sh
office-use watch ./draft
```

A mismatch is a review candidate, and a match covers only the compared points. `complete: false` identifies missing caches, unsupported sources, chart extensions, charts without recognized references or limits. Inspect the chart and source workbook in the destination application before delivery.

The scan covers at most 50 chart parts, 100 references, 2,000 source cells per reference and 10,000 source cells overall; chart XML is limited to 4 MiB per part. It returns at most 20 mismatch examples per reference with values clipped to 500 characters. It does not calculate formulas, refresh caches or change the workbook. Save and close external editing sessions first.

For a fully comparable mismatch, `session sync-chart-cache` or MCP `session_sync_chart_cache` copies stored worksheet values into one selected chart reference, updating or adding points for verified values and removing points for verified blank cells, and creates a new revision. Use the chart `part` and one-based `reference` index from a fresh scan; a chart part can be shared by multiple placements. The operation rejects unverified values, escaped Excel text, chart extensions, external data and signed packages. It preserves other package parts and reserializes the selected chart XML. Source formulas require an explicit `--allow-formula-caches` / `allow_formula_caches: true` opt-in to use their saved results; recalculate first when appropriate. The viewer offers sync for eligible mismatch candidates in the latest revision and requires formula sources to be handled separately. Rescan and inspect the chart after syncing; formula cache freshness remains unknown.

Formula scans also expose `dynamic_array_metadata` (`true`, `false`, or `null`) and `dynamic_array_metadata_issue`. Detection covers XLDAPR metadata markers; other unsupported structures can require separate review. Review bundles flag detected or uninspectable metadata. LibreOffice recalculation refuses detected or uninspectable dynamic-array metadata by default because spill results may be incomplete. To explicitly proceed with a separately saved result, pass `--allow-dynamic-arrays` to either recalculation CLI command, `allow_dynamic_arrays: true` to the MCP tool, or select the corresponding checkbox in the viewer. Compare the new file and recalculate in a compatible application when needed.

`scan-formulas` scans stored cells across worksheets, including hidden sheets, and reports counts and the first 200 formula errors, literal error cells, and empty or missing formula caches in separate lists. Formula text is OOXML text without a leading `=` and is clipped to 500 characters; shared-formula followers may have empty formula text. An empty cached string can be intentional. `complete: false` means the one-million-cell limit stopped the scan and counts cover only scanned cells; package limits are 5,000 parts and 128 MiB. The scan also reports the explicitly stored workbook calculation mode and per-sheet `fullCalcOnLoad` requests; `calculation_metadata_complete` and per-sheet metadata issues indicate whether those properties were inspected. Absence of a request leaves cache freshness unknown. The review bundle flags saved requests and incomplete calculation metadata. This scan does not calculate formulas or determine whether existing caches are current. `cells` reports formulas, their stored cached values, and cell types, including formula errors. Cache freshness is always `unknown`; a missing cached result is returned as `null`. Rows include blank cells in the requested rectangle. `recalculate` opens a copy in a fresh LibreOffice profile configured to recalculate OOXML formulas on load ([LibreOffice formula options](https://help.libreoffice.org/latest/en-GB/text/shared/optionen/01060900.html)), saves a new XLSX, and refuses an existing output. It restores the source workbook’s explicitly saved calculation mode after conversion, and rejects signed or oversized packages. Read the output again to inspect calculated values and errors. LibreOffice uses its own calculation engine and may change other calculation settings, layout or unsupported workbook features; review the resulting file against the source. External links, advanced Excel functions, complex workbooks and fidelity have not been comprehensively validated. Use a saved, closed source and review workbooks containing external links before conversion.


For a versioned XLSX session, scan its latest saved revision and explicitly recalculate into a new revision:

```sh
office-use session start ./budget-draft --source budget.xlsx
office-use session scan-formulas ./budget-draft --base 0
office-use session recalculate ./budget-draft --base 0
office-use session scan-formulas ./budget-draft --base 1
```

The equivalent MCP tools are `session_scan_formulas` and `session_recalculate`. Both require the latest base revision; competing writes are rejected. The local viewer's “Workbook calculation and checks” offers both operations, clears obsolete scan results, and keeps pending edits available. The scan examines saved caches; LibreOffice recalculation creates a new revision and may alter workbook features. Compare the revisions and inspect resulting errors and layout before delivery.
