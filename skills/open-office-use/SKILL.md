# Open Office Use

Use `office-use --help` for installed commands and [the project guide](https://github.com/trotsky1997/open-office-use/blob/main/office/README.md) for installation, MCP setup, specifications and limitations. The skill provides guidance; install the CLI and optional MCP dependency separately. If capabilities fail or the environment is unfamiliar, run `office-use doctor` or call `office_doctor` to check dependencies; version probes do not verify output fidelity. For multi-step work, use a session directory and pass the latest revision as the base for each edit. The viewer can preview or compare earlier revisions, including bounded text, file-part and XLSX cell diffs, before `session_restore` or its restore control copies a prior revision into a new revision when requested. When a user wants to watch progress, run `office-use watch` for the session and share its local URL. The viewer can search a saved selection for candidate paths; the user can choose a candidate to load. For XLSX, the viewer and MCP can load and edit a bounded grid, with formulas marked by `=` and explicit version checks. The viewer supports rectangular tab-separated grid paste with bounds and formula protection. Grid formatting supports bold, RGB fill and number formats for a selected subrange. For a unique literal replacement in a simple Word body or table-cell paragraph, a supported PowerPoint shape or table-cell paragraph, or an Excel text cell, use `session_replace_text` to retain run formatting; Word matches must stay within hyperlink or annotation boundaries. Excel formula caches may become stale; inspect and recalculate when appropriate. Other structural restrictions apply. The viewer and MCP can also load and edit supported elements by explicit path; verify the element and version first. If the user selects an area, read `session_selection`, `session_selection_image` and, when useful, `session_selection_text` and `session_selection_candidates`; check its revision and stale flag, then verify candidate elements with structured reads and visual context. PowerPoint selection candidates can also match visible shape geometry when page mapping is reliable, including images; verify geometry matches and text matches against the rendered slide. Repeated or missing text can produce ambiguous results. Selected PDF text may omit image or partially selected text. Inspect source files before editing. Write to a new output path. For structured operations use OfficeCLI through `office-use structured` and `office-use batch` when installed. Save and close the source first. Use `review_document_bundle` or `session_review_bundle` for one-snapshot audit, format-specific checks and visual overview, and inspect their report before delivery. `audit` or `audit_file` can also be used independently. Use `compare` or `compare_files` to review text and package changes in saved files; use `compare_page_images` or `session_compare_page_images` for corresponding rendered page comparisons; inspect the actual content and rendered pages for details. Use `session_add_comment` for a plain-text review comment on a Word body or table paragraph; pass a unique literal `anchor` to target text within adjacent runs, or omit it to cover a simple paragraph. Existing supported modern comment metadata is updated alongside the new root. Use `list_word_comments` or `session_list_comments` to inspect bounded comments and main-body anchor hints. Word 2013 comment thread parents and resolved status are reported when metadata maps unambiguously; unmatched or malformed states remain unknown. Use `session_reply_comment` to reply to a supported open root comment and `session_resolve_comment` to resolve or reopen one in a new revision. For an embedded PowerPoint picture, use `session_replace_picture` with a local PNG or JPEG and inspect the rendered revision; the existing crop remains. For PowerPoint, use `inspect-layout` / `inspect_slide_layout` or `session_inspect_slide_layout` to locate off-slide and overlap candidates; inspect the completeness flags, verify paths and distinguish intentional layering. Use `view_contact_sheet` or `session_contact_sheet` for a numbered multi-page overview, then use `view_document_page` or `session_view_page` to inspect individual rendered pages and optional normalized crops before delivery, including text overflow and master content. Use `scan-formulas` or `scan_formulas` to check stored formula caches and error cells across worksheets, checking its completion and truncation flags. Use `cells` or `read_cells` to inspect formulas and cached values, and `compare-cells` or `compare_cells` for range-level value, formula and direct-formatting changes. Check `text_comparison_complete`; review conditional formatting and theme changes separately. Cache freshness is unknown. When appropriate, use `session_recalculate` for a new XLSX session revision or `recalculate` / `recalculate_workbook` for a separate LibreOffice-calculated copy; use `session_scan_formulas` to check the latest session revision, inspect errors, and review conversion fidelity. Inform the user about any fidelity or feature limitations relevant to their file.

For PowerPoint shape and table text, use `search_slide_text` or `session_search_slide_text` to locate candidate edit paths. Check coverage and follow `next_offset` with the same query, slide and snapshot hash. Inspect the slide before editing.

For PowerPoint speaker notes, use `read_slide_notes` or `session_read_slide_notes` with a one-based slide number. Use `session_replace_slide_notes_text` for a unique literal replacement within a one-based simple paragraph, retaining run formatting. `session_replace_slide_notes` creates a revision and replaces the entire notes text, resetting its formatting; inspect the result and keep the original revision for reference.

Use `compare_slide_notes` or `session_compare_slide_notes` to compare corresponding speaker notes when reviewing a deck or session; select slide numbers on both sides and check truncation.

To propose a tracked Word replacement in a supported body, header or footer paragraph, use `session_track_replace_text` with a unique match and author; review the new revision and its limitations. For header or footer revisions, inspect `story_impact` for shared section links before editing. For an insertion before or after a unique anchor, use `session_track_insert_text` and retain the returned revision ID. For documents with possible tracked revisions, use `list_word_tracked_changes` or `session_list_word_tracked_changes`; inspect coverage, XML context and formatting before deciding how to proceed. XML records are not direct edit paths. For a user-authorized accept or reject decision, `session_resolve_tracked_runs` can resolve selected supported insertion/deletion run IDs within one part; verify coverage and review the new revision.

For Word body and nested table text, use `search_word_body` or `session_search_word_body` to find candidate edit paths; check coverage and continue with the same query, `next_offset` and `snapshot_sha256` as needed. Inspect the target before editing.

For Word headers and footers, use `list_word_stories` or `session_list_word_stories` to obtain relation-ID paragraph paths, then `session_replace_text` for a unique literal match. Inspect `linked_sections`, `same_part_ids` and `reference_resolution_complete` before editing a shared part; first/even page display depends on document settings and pagination, so inspect the rendered document.

For XLSX editing, check `session_read_grid` for `sheet_protected`, cell `read_only_reason` and `merged_anchor`. Use the merge origin and preserve worksheet protection; explicitly unlocked cells on a protected sheet remain editable.

For an XLSX overview, use `inspect_file` or `session_inspect_workbook` to obtain a bounded sparse sample across worksheets; check sample and truncation flags and use `read_cells` for detailed decoded values. To locate literal text or formulas beyond the sample, use `search_cells` or `session_search_cells` and check scan, match and text coverage flags. Continue with `next_offset` and `snapshot_sha256`, retaining the same query and sheet, until the scan finishes.

Range reads use one saved snapshot and have a response size limit; narrow a range on a limit error. Grid cells longer than 4,000 UTF-16 units or with unverified text are read-only; literal text containing Excel escape-like sequences is rejected by the grid, single-cell editor and author; use supported targeted text replacement when appropriate.

After editing XLSX chart source cells, use `scan_chart_caches` or `session_scan_chart_caches` and inspect mismatches, missing caches and coverage. Formula caches may be stale and chart rendering still needs review.

For a supported chart-cache mismatch, `session_sync_chart_cache` updates one reference from saved source values in a new revision. Check formula cache freshness before explicitly opting in to formula sources; rescan and inspect the chart after syncing.

Use `office_schema` to discover the installed OfficeCLI elements and property definitions before constructing unfamiliar structured operations. Filter by format, operation and query; verify the resulting document and rendering.

Use `dump_office_subtree` or `session_dump_office_subtree` to extract a bounded starting batch from a saved template. Review paths and dependencies before applying; charts and sibling resources can be omitted, and slide layouts may require a compatible template. Compare and render the replayed document.

For header and footer text, use `search_word_stories` or `session_search_word_stories`; page through results using the snapshot hash and inspect shared-section impact before editing.

For PowerPoint deliverables, use `inspect_slide_text` or `session_inspect_slide_text` to locate candidate text-box and table-cell rendering problems, including supported nested groups, review coverage and inspect the rendered slides.

For worksheet presentation, `session_format_grid` applies font, color, alignment, wrap, fill and number formatting to a supported loaded range; inspect the resulting revision and rendered workbook.

To size worksheet rows or columns, inspect the grid dimension metadata and use `session_resize_grid`; changes affect complete rows or columns, including cells outside the selected range.

Use `session_compare_cells` to review formulas, cached values, direct formatting and stored row/column dimensions between revisions. OfficeCLI XLSX batches may update formula caches; `session_resize_grid` and `session_format_grid` preserve cached values.

XLSX targeted text replacement requests sheet recalculation on load while retaining existing caches; inspect `session_scan_formulas` and use explicit recalculation when appropriate. LibreOffice uses its own formula engine and may alter workbook features.

Use `session_edit_grid` for bounded multi-cell value and formula edits; XLSX `session_edit` shares this cache-preserving path for a single cell and supports `literal` mode for text; set `type: "text"` on nonempty changes to retain literal values such as `00123` or `=literal`; unchanged formula caches are retained, changed formulas lose their caches, and sheet recalculation is requested. When formulas change, a validated saved calculation chain is removed for rebuilding; ambiguous chain metadata is rejected.

Use `session_replace_text_batch` for 1–25 ordered, explicit text replacements that must commit as one revision. Each change supplies `path`, `find`, and `replacement`; inspect targets first and review the result.

Grid and XLSX single-cell editing can create supported dynamic-array formulas when XLDAPR metadata and candidate tokens validate. Their spill range and cached results require review in a compatible calculation application; local LibreOffice testing did not populate a SEQUENCE spill. Existing array anchors and saved ranges are read-only.
